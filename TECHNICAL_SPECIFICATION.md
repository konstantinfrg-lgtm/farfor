# Техническое задание

**на разработку сайта-каталога коллекции фарфоровых молочников**

## 1. Общая информация о проекте

**Название проекта:**
Сайт для ведения и демонстрации коллекции фарфоровых молочников.

**Цель проекта:**
Создать веб-сайт, на котором можно:

- вести каталог коллекции фарфоровых молочников;
- добавлять новые экземпляры с несколькими фотографиями;
- систематизировать коллекцию по заданным полям;
- искать, фильтровать и сортировать предметы;
- отображать как личную коллекцию пользователя, так и общую коллекцию всех пользователей.

**Тип проекта:**
Веб-приложение / сайт-каталог с личным кабинетом.

---

## 2. Цели и задачи системы

### 2.1. Основные цели

- Обеспечить удобное хранение информации о предметах коллекции.
- Создать единый классификатор для каталогизации молочников.
- Обеспечить визуальное представление каждого предмета через фотогалерею.
- Реализовать многопользовательский режим с регистрацией и авторизацией.
- Дать возможность пользователю просматривать только свою коллекцию или всю базу.

### 2.2. Основные задачи

- Разработать публичную часть сайта.
- Разработать административную / пользовательскую часть.
- Реализовать карточки экспонатов.
- Реализовать фильтрацию и поиск.
- Реализовать добавление, редактирование и удаление экземпляров.
- Реализовать загрузку нескольких фото.
- Реализовать управление видимостью коллекций.

---

## 3. Целевая аудитория

- Частные коллекционеры фарфора.
- Исследователи и любители декоративно-прикладного искусства.
- Пользователи, заинтересованные в систематизации частных коллекций.
- Администратор сайта.

---

## 4. Функциональные требования

### 4.1. Роли пользователей

#### 4.1.1. Гость

Без авторизации может:

- просматривать публичную часть сайта;
- просматривать общую коллекцию, если она открыта для публичного просмотра;
- пользоваться поиском и фильтрами;
- просматривать карточки предметов.

#### 4.1.2. Зарегистрированный пользователь

После авторизации может:

- вести свою коллекцию;
- добавлять новые экземпляры;
- редактировать свои записи;
- удалять свои записи;
- загружать несколько фотографий для одного экземпляра;
- выбирать режим просмотра:
  - только моя коллекция;
  - все коллекции;
- управлять настройками видимости своих записей.

#### 4.1.3. Администратор

Может:

- управлять всеми пользователями;
- просматривать, редактировать и удалять любые записи;
- модерировать контент;
- управлять справочниками / классификаторами;
- блокировать пользователей;
- настраивать общие параметры сайта.

### 4.2. Регистрация и авторизация

Система должна поддерживать:

- регистрацию нового пользователя;
- вход по email и паролю;
- восстановление пароля;
- выход из аккаунта;
- подтверждение email — желательно;
- защиту форм от спама.

Требования:

- пароль хранить только в хэшированном виде;
- использовать безопасную аутентификацию;
- предусмотреть защиту от подбора пароля;
- предусмотреть CAPTCHA или аналогичную защиту при регистрации.

### 4.3. Личный кабинет пользователя

В личном кабинете должны быть доступны:

- профиль пользователя;
- список его предметов коллекции;
- кнопка добавления нового предмета;
- редактирование существующих карточек;
- настройки видимости коллекции;
- переключатель режима просмотра:
  - **Моя коллекция**
  - **Все коллекции**

### 4.4. Каталог коллекции

Каждый экземпляр коллекции должен храниться в виде отдельной карточки.

Обязательные поля карточки:

- Производитель
- Скульптор
- Художник
- Название формы
- Название росписи
- Год создания / период создания
- Комментарии

Дополнительные рекомендуемые поля:

- Название предмета
- Материал
- Страна
- Завод / фабрика
- Высота
- Объем
- Состояние предмета
- Наличие клейма
- Описание клейма
- Источник поступления
- Дата добавления в коллекцию
- Статус публикации
- Владелец записи

### 4.5. Работа с фотографиями

Для каждого экземпляра должна быть возможность:

- загрузить несколько фотографий;
- назначить главное фото;
- удалять отдельные фото;
- менять порядок фото;
- открывать фото в увеличенном виде.

Требования к фото:

- поддержка форматов JPG, JPEG, PNG, WEBP;
- автоматическое создание уменьшенных копий;
- ограничение по размеру файла;
- защита от загрузки недопустимых файлов.

### 4.6. Поиск, фильтрация и сортировка

Система должна поддерживать поиск по каталогу.

Поиск:

- по названию предмета;
- по производителю;
- по скульптору;
- по художнику;
- по названию формы;
- по названию росписи;
- по комментариям.

Фильтрация:

- по производителю;
- по скульптору;
- по художнику;
- по названию формы;
- по названию росписи;
- по периоду / году создания;
- по владельцу коллекции;
- по наличию фото;
- по статусу публикации.

Сортировка:

- по дате добавления;
- по названию;
- по году создания;
- по производителю.

### 4.7. Видимость коллекций

Необходимо реализовать логику отображения коллекций.

Пользователь должен иметь возможность:

- просматривать только свои предметы;
- просматривать общую базу всех пользователей;
- отмечать записи как:
  - публичные;
  - доступные только владельцу;
  - доступные всем зарегистрированным пользователям.

### 4.8. Административная панель

В административной панели должны быть функции:

- управление пользователями;
- просмотр всех коллекций;
- редактирование карточек;
- удаление карточек;
- модерация фотографий;
- управление справочниками:
  - производители;
  - скульпторы;
  - художники;
  - формы;
  - росписи;
- настройка ролей и прав доступа;
- просмотр статистики.

## 5. Структура сайта

Рекомендуемая структура разделов:

1. **Главная страница**
   - краткое описание проекта;
   - поиск по коллекции;
   - новые добавления;
   - избранные экземпляры.
2. **Каталог**
   - список всех доступных предметов;

   - фото;
   - описание;
   - атрибуты;
   - информация о владельце (если разрешено).
4. **Личный кабинет**
   - мои предметы;
   - добавить предмет;
   - настройки профиля;
   - настройки видимости.
5. **О проекте**
6. **Контакты**
7. **Вход / регистрация**
8. **Админ-панель**

## 6. Сценарии использования

### Сценарий 1. Регистрация

Пользователь открывает сайт, проходит регистрацию, подтверждает email и получает доступ в личный кабинет.

### Сценарий 2. Добавление нового молочника

Пользователь нажимает «Добавить предмет», заполняет карточку, загружает несколько фотографий, сохраняет запись.

### Сценарий 3. Поиск по коллекции

Пользователь вводит в поиск, например, производителя или название формы, получает список подходящих предметов.

### Сценарий 4. Просмотр только своей коллекции

Пользователь в личном кабинете включает режим «Моя коллекция» и видит только собственные записи.

### Сценарий 5. Просмотр общей базы

Пользователь переключает режим на «Все коллекции» и видит записи других пользователей в рамках настроек доступа.

## 7. Нефункциональные требования

### 7.1. Производительность

- сайт должен быстро открываться на десктопе и мобильных устройствах;
- каталог должен поддерживать пагинацию;
- страницы карточек должны открываться без заметных задержек.

### 7.2. Безопасность

- защита от SQL-инъекций, XSS, CSRF;
- безопасное хранение паролей;
- разграничение прав доступа;
- проверка прав на редактирование и удаление объектов;
- резервное копирование базы данных и изображений.

### 7.3. Адаптивность

- сайт должен корректно работать на:
  - компьютерах;
  - планшетах;
  - смартфонах.

### 7.4. Масштабируемость

- архитектура должна позволять расширять справочники;
- должна быть возможность в будущем добавить:
  - избранное;
  - комментарии;
  - экспорт в Excel / PDF;
  - метки и теги;
  - API;
  - многоязычность.
